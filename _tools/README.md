# アニメ語り図書館の作り方

`_` で始まるフォルダ（`_anime` `_transcripts` `_tools`）は GitHub Pages では公開されません。

## 1本追加する手順
1. YouTube Studio から字幕（.sbv）をダウンロード
2. 発言全文を作る（その作品を語っている範囲を秒で指定）
   python3 _tools/transcript.py captions.sbv 開始秒 終了秒 _tools/dict_<slug>.tsv > _transcripts/<slug>.md
   ↑これは下書き。仕上げとして Claude に次のルールで整えてもらう（全記事共通）
   - 明らかな誤字脱字は直す。「あ」「や」など意味をなさない断片や言い淀みは削除するか、文として成り立つように整える
   - 話し言葉の口調・言い回しは残す（要約・言い換えはしない）
   - 2〜4文ごとに段落を分け、読みやすくする
   - 発言の言い間違い・事実の誤りは本文を書き換えず `〔注：…〕` で訂正を添える（ページ上では「注」として表示）
   - 読み上げた視聴者コメントは `（コメント：…）` と書く（ページ上ではコメントの吹き出しになる）。視聴者の名前は載せない（体験談などコメントの内容は、名前がなければそのまま残してよい）
3. 記事を `_anime/<slug>.md` に書く（AIに下書き → 本人が確認）
   - 見出しの末尾に `<!-- t=秒 -->` を付けると、▶ボタン・目次・動画の見どころ情報が入る
   - 末尾の `<!-- highlights -->` 以下の箇条書きが「ことはの注目ポイント」になる
   - `category` はチャンネルの分類（布教解説／アニメ感想／アニメ発掘／演出解剖／イベント・上映会）。分類の説明文は `build.py` の `CATEGORY_NOTES`
   - `spoiler_level` は一覧に出すネタバレの程度（なし／序盤／一部／終盤／重大／結末）。一覧には人物の最期や正体などの中身を出さない
   - `spoiler` は具体的な範囲。記事ページで「詳しい範囲を見る」を開いた人だけが読めます
4. `python3 _tools/build.py` → `anime/<slug>.html` と `anime.html` と `sitemap.xml` が更新される
   - 記事（`_anime/*.md`）を削除・改名した場合、元の記事がなくなった古い `anime/*.html` は自動で削除されます
   - `sitemap.xml` には、ホーム・`anime.html`・`quiz.html` と、下書き（`status: draft`）以外の記事が載ります。ページを増やしたときは `build.py` の `SITEMAP_PAGES` に追加
   - 生成の前に入力チェックが走り、slug の重複・ファイル名との不一致、見出し秒数が segment の範囲外、発言全文や注目ポイントの書き忘れ、日付や分類の書き間違いがあると、理由を表示して止まります
   - `python3 _tools/build.py --check` は何も書き換えずに、公開中のHTMLが記事データと一致しているか（再生成し忘れがないか）だけを確かめます。コミット前に実行してください
   - 冒頭の設定欄に `published`（記事を公開した日）と `note`（「◯月の配信を記事化」など）を書く。`streamed` は配信日のまま
   - 本文は配信時点の感想として書き、記事化のときに分かった訂正・補足は `note` や本文中の補足として分けて書く
5. 確認が済んだら `status: draft` の行を消して再ビルド（記事の検索除けが外れる）

必要なもの: Python 3、`pip install markdown pyyaml`
